# 내 대화에서 업무 데이터 만들기

앱은 업무를 수집하는 봇이 아닙니다. 로그인된 Discord·Notion 화면을 사람이 확인하거나 Codex가 브라우저로 읽은 뒤, 정리한 결과를 `local/tasks.json`으로 저장해 사용합니다. Codex 없이도 [데이터 형식](DATA.md)에 맞게 직접 작성할 수 있습니다.

## 수집 전에 정할 것

| 항목 | 예 |
| --- | --- |
| 내 계정·서버 별명 | 본인 Discord 사용자명과 서버 표시 이름 |
| 확인 범위 | 특정 서버, 프로젝트 채널, 필요하면 지정한 DM |
| 기간 | 어제·오늘 또는 명시한 시작일과 종료일 |
| 내 프로젝트 목록 | 본인의 실제 프로젝트를 새로 정하고, 서로 다른 프로젝트는 분리 |
| 완료 기준 | 리뷰 완료, 질문 해소, 요청한 변경의 적용 확인 등 |

다른 사람에게 온 태그와 내 태그를 혼동하지 않게 계정과 서버 별명을 함께 확인합니다. 서버별 검색은 그 서버만 포함합니다. 다른 서버·DM도 보려면 수집 범위에 별도로 포함해야 합니다.

## 읽는 순서

1. **받은 멘션**을 확인합니다. 직접 태그뿐 아니라 내가 속한 역할 태그도 봅니다.
2. **내가 작성한 메시지**도 찾습니다. 내가 요청한 일, 내가 한 질문, 공유가 여기에 있습니다.
3. 각 메시지의 **앞뒤 대화와 스레드 후속 내용**을 읽습니다. 답변이 왔다는 사실과 실제 해결은 다릅니다.
4. PR이나 이슈가 연결되어 있으면 접근 가능한 범위에서 상태를 확인합니다. 내 리뷰가 작성 중인지 제출됐는지, 다른 사람의 승인인지 구분합니다.
5. 같은 요청의 재태그·리마인드·승인 알림을 원래 항목에 묶습니다. 별도 요청이면 같은 스레드 안에서도 항목을 나눕니다.
6. 정리한 데이터를 저장하고 형식 검사를 실행합니다.

Discord 검색 필터의 표시 언어가 다르면 검색창의 사용자·날짜 필터 메뉴를 사용합니다. 결과가 0건이라고 해서 내가 작성한 메시지가 없다고 바로 판단하지 않습니다.

## 맥락 분류

| 분류 | 사용할 때 | 완료 판단 |
| --- | --- | --- |
| 내 할 일 `mine` | 나에게 실행·검토·결정 등을 요청함 | 내가 맡은 검토·결정·조치가 실제로 끝남 |
| 요청한 일 `requested` | 내가 다른 사람에게 작업을 맡김 | 상대방의 완료 보고나 결과물을 확인함 |
| 내가 한 질문 `question` | 내가 설명·선택·결정 근거 등을 물음 | 궁금한 쟁점이 해소됨 |
| 공유 `shared` | 정보·일정·진행 상황을 알림 | 작업 요청과 분리해 공유 탭에 둠 |

리뷰 봇이 `Assignees / Reviewers`를 표시하면 **내가 어느 쪽에 포함됐는지** 봅니다. 내가 Reviewers이면 내 리뷰 요청, 내가 Assignees이고 다른 사람이 Reviewers이면 내가 작성한 변경의 리뷰 진행 상황입니다.

업무 종류는 디자인·기획·리뷰·마케팅 중 하나를 선택합니다. 리뷰는 대상이 디자인이든 문서든 `review`로 분류합니다. 프로젝트는 채널 이름만 복사하지 말고 대화의 실제 주제를 봅니다. 다른 사용자의 프로젝트 구성은 이어받지 않습니다. 사용자가 통합을 명시하지 않으면 서로 다른 프로젝트를 합치지 않습니다. 판단할 근거가 없으면 임의로 기한·담당자·완료를 확정하지 않고 `note`에 확인할 점을 남깁니다.

‘내일’, ‘금요일’ 같은 일정은 **메시지를 작성한 날짜와 시간대**를 기준으로 해석합니다. 사용자가 별도로 정하지 않은 기한을 만들지 않습니다. 지금 형식에는 전용 기한 필드가 없으므로 확정된 일정은 제목·설명에 구체적인 날짜로 표시합니다.

## Codex에 복사할 프롬프트

아래 대괄호 부분을 자신의 정보로 바꾸고, 이 프로젝트 폴더를 연 Codex 채팅에 붙여넣습니다. 개인 파일을 수정하는 작업이므로 먼저 중요한 `local/` 데이터를 백업해 두면 되돌리기 쉽습니다.

```text
이 저장소의 README.md, docs/DATA.md, docs/COLLECT.md를 읽고 내 업무 데이터를 갱신해 줘.

내 계정: [Discord 사용자명 / 서버 별명]
범위: [서버·채널·프로젝트, 포함할 DM이 있다면 명시]
기간: [시작일 ~ 종료일, 시간대]
내 프로젝트 목록: [본인 업무에 맞게 새로 지정 / 처음이면 대화를 보고 분리안을 제안]
예외 통합: [내가 명시적으로 합치려는 프로젝트만 기재 / 기본값은 통합 없음]

이미 로그인한 기존 브라우저 탭이나 스페이스에서 Discord를 확인해 줘.
새 세션을 만들거나 저장된 로그인 정보를 초기화하지 말고,
로그인이 필요하면 내가 로그인할 수 있도록 알려줘.
인증 토큰을 추출하는 방식 대신 연결된 도구나 브라우저 화면을 사용해 줘.

받은 멘션과 내가 작성한 메시지를 모두 확인해 줘.
내 할 일 / 요청한 일 / 내가 한 질문 / 공유로 맥락을 분류하고,
업무 종류는 디자인 / 기획 / 리뷰 / 마케팅으로 나눠 줘.
앞뒤 대화와 후속 결과까지 보고, 단순 답변·반응만으로 완료하지 마.
프로젝트는 내 업무에 맞게 정하고, 서로 다른 프로젝트는 기본적으로 분리해 줘.
다른 사람의 프로젝트 목록이나 통합 설정을 복사하지 마.
같은 요청의 알림은 묶고 원문 및 완료 판단 근거 링크를 남겨 줘.

기존 local/tasks.json을 읽고 같은 작업의 ID는 유지해 줘.
수집 범위 밖의 기존 항목을 지우지 말고, 명시적으로 종료된 항목만 상태를 갱신해 줘.
local/state.json의 수동 완료 상태는 바꾸지 말아 줘.
기존 수동 완료와 새 대화가 충돌하면 나에게 알려줘.

확인한 내용으로 local/tasks.json을 갱신한 뒤
python3 server.py --check로 형식을 검사해 줘.
수집하지 못한 범위와 완료 판단이 불명확한 항목도 알려줘.
```

Windows에서는 마지막 명령을 `py -3 server.py --check`로 바꿉니다. 사용하는 Codex에 브라우저 도구가 없다면 대화 내용을 직접 전달하거나 수동 입력이 필요합니다.

## 이후 갱신

필요할 때 수동으로 수집하거나 [정기 갱신 설정](UPDATE.md)에 따라 매일 한국 시간 09·12·17시의 수집 자동화를 등록합니다. 예약은 사용자별로 등록하며, 이 저장소를 내려받는 것만으로 실행되지는 않습니다.

수집 도구는 `local/collection.json`에 범위와 마지막 성공 지점을 기록합니다. 다음 실행에서는 그 이후 새 대화만 추가하고, 기존 미완료 항목은 원래 날짜와 관계없이 후속 확인합니다. 파일이 없는 첫 실행은 사용자가 지정한 시작일부터 확인합니다. 기존 목록만 있다면 마지막 항목의 작성 시각부터 이어서 확인하되 같은 메시지는 중복 추가하지 않습니다. 상세 절차와 실패 시 처리 기준은 정기 갱신 가이드를 따릅니다.

같은 작업의 ID를 바꾸면 앱이 새로운 항목으로 인식합니다. ID를 유지해야 사용자가 완료한 기록이 보존됩니다. `initial`은 대화에서 확인한 상태이고, 화면에서 직접 바꾼 상태는 `local/state.json`이 우선합니다. 후속 대화로 다시 열어야 한다고 판단되면 화면에서 직접 되돌립니다.

수집 파일의 변경은 화면으로 돌아올 때 또는 화면을 보는 동안 1분 이내에 반영됩니다. 날짜는 기본적으로 전체 기간을 보여줍니다. 화면의 5초 상태 확인은 다른 브라우저의 완료·되돌리기를 반영하며, 대화 수집을 대신하지 않습니다.

## Notion 멘션을 함께 수집하기

Notion을 추가할 때 사용할 워크스페이스 URL, 본인 표시 이름, 첫 수집 시작일을 개인 수집 설정에 적습니다. 이고라이트의 로그인된 세션에서 수신함을 열고, 읽음 여부와 관계없이 해당 기간의 직접 멘션·리뷰 요청을 확인합니다. 참여자 속성에 이름이 들어갔다는 이유만으로 할 일로 분류하지 않습니다.

알림을 클릭해 원문 페이지와 댓글의 후속 답변을 읽습니다. 접힌 답글이나 더 보기 안의 내용도 확인하며, 상태 속성만으로 개인 리뷰가 끝났다고 단정하지 않습니다. 이미 답변·처리된 요청은 실제 근거에 따라 반영합니다. 수신함만으로는 본인이 작성한 모든 댓글을 찾을 수 없으므로, 수집 범위는 멘션과 연결 페이지의 후속 확인임을 구분합니다.

`source=notion`, `url=해당 페이지·블록·댓글로 이동하는 URL`로 저장합니다. 알림과 페이지 본문·댓글에 있는 링크는 `links`에 이름과 URL을 함께 저장합니다. 본문 링크가 있다는 사실은 완료 근거가 아니므로 `evidence`와 구분합니다. Discord 메시지 본문 링크에도 같은 규칙을 적용합니다.

동일 작업이 Discord와 Notion에 모두 있으면 기존 ID를 유지하고 요청 내용·결과물 링크를 비교해 합칩니다. 원래 출처는 `evidence`에 보존하고 현재 확인할 위치를 `url`로 지정합니다. 제목이나 프로젝트가 비슷하다는 이유만으로 다른 요청을 합치지 않습니다. Notion의 날짜·시각은 알림 또는 댓글의 정확한 작성 시각을 확인하며 상대 시간으로 임의 추정하지 않습니다.

수집 지점은 서비스별로 관리합니다. 새로 추가한 Notion은 Discord의 마지막 성공 시각을 이어받지 않고 별도로 과거 멘션을 확인합니다. 일부 기간을 확인하지 못하면 Notion 경계를 전진시키지 않고 남은 범위를 기록합니다.
